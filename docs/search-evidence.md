# 检索记录与技术相关性

0.2.0第三阶段修复查询截断和后续要素漏查；0.3.0 的相关性关卡由大模型逐项复核填写，历史验证记录保留。查询执行成功只证明请求得到响应，不证明检索充分或找到了相关技术。

## 查询与正文的两个预算

0.4.0 不填自定义词时先安排全部原要素，再按轮次补充审核通过的词典/LLM变体。理论类最多8条，工程类最多16条；未显式传策略的API默认保守理论策略。工程类可组合两个不重叠术语，理论类只单术语替换。完整四层和质量/成本Eval见[同义词说明](synonym-expansion.md)。单条最多400字；用户词超长直接报错，不联网；要素超长或查询预算不足时保留原文及未发送原因，不机械裁掉后半句。编号只表示该要素的查询范围，不能证明查询表达充分。

Google Patents 每条查询最多保留5个候选；[智慧芽](patsnap-search.md)默认5个，可选1–25个。全部计划内查询完成后按公开号去重，再按部件覆盖、关系/限定及提及语境的规则提示排序。保留原词汇分数、旧排名与不同查询返回的标题/摘要（平台提供时），不删除低分或未知候选。可按需确认外发后调用模型作元数据相关性重排；只影响阅读顺序。详见[候选排序与补取](candidate-ranking.md)。正文读取次数受独立文献预算约束，失败也计入，不无限重试；预算外候选保留为 `not_selected`。早期查询取得文献不会阻止后续查询。

自定义词保持用户指定范围，不自动拼入LLM或逐要素扩展，也不能宣称覆盖整套要素。本轮未发出的查询、失败、空结果、无效来源、正文失败和未读候选均进入报告限制；存在这些缺口时不输出“未发现完整披露”。这可能产生较保守的结果，不能把预算限制解释为已经排除其他候选。

## 记录与重新对照

`search_audit` 第1版增加可选的 `expansion`（策略、保护术语、候选状态/来源/审核和变体）及 `retrieval_cost`（实际查询、正文尝试、返回数、生成成本与耗时），旧记录仍可读。保存要素/基准日绑定、实际术语表、查询预算、正文预算、每条实际查询及要素编号、起止时刻、返回数量与候选标题/摘要/链接/公开号。候选另保存来自哪些查询、全部不同摘要观测、词汇/关系规则提示、原词或扩展来源、元数据模型判断、获取状态及错误。追加正文保存独立尝试和成本，不重新发查询；有效的既有正文复核保留。报告用 `retrieval_increment` 区分扩展独有候选、元数据相关和正文相关；原词查询不全时不确认增量归因。程序的“返回数量”是检索器交付的有限列表数，不是 Google 的全库命中总数。

网页中的“本轮检索范围与记录”、JSON和Markdown均可查看这些记录。继续模型复核、补快照或生成模型建议时传递同一 `search_audit`；要素或基准日改变使旧记录失效。重新复核不产生新的在线查询。未给出检索记录的显式快照比对标为 `provided_snapshots`，不补造检索历史；历史报告无记录时标为未记录。

在线后补入的人工快照仍记录人工来源，不替换原查询/候选历史；重新对照的快照哈希以当前报告文献为准，原在线获取哈希留在检索记录中。两者不可混称。

## 相关性仍须有依据

规则排序只决定先获取哪些候选，不自动作相关或不相关判断。可选模型标题/摘要判断单独标为 `model_metadata`，逐要素附引文，只作重排；不能成为正文复核或新颖性依据。不同装置可能有相关部件，不能只凭标题排除；高词汇重合也不证明技术关系、数值、否定或动作顺序一致。

相关性默认为 `unknown`。0.3.0 由模型逐项复核返回 `related`、`unrelated` 或 `unknown`，并附依据和有效原文位置；与模型来源、时刻、要素、基准日、快照及逐项对照一起绑定。输入或模型设置变化后须重新复核，旧确认不沿用；模型输出不标成人工确认。

全不相关或尚未确认时保持证据不足。当前规则也将文献集中尚有不相关或未读候选视为排除结论的缺口；至少一篇经有效复核确认同一方案完整披露时，仍报告风险并列出其他缺口，不隐藏已证实的风险。

新字段不会把旧复核自动升级为有效记录；旧报告与快照不修改。基础合成夹具显式模拟相关性及出处，参考标签保持原样；夹具版本递增为3，不是真实人员提交或专业正确性认证。
