# 智慧芽查询与原文

当前编译版本为 `patsnap-concepts-v2`，实现于 `modules/patsnap_query_plan.py`。只接收公开确认要素和已审核扩展，不接收金标或评分反馈。

## 从术语到查询

1. `generate_llm_candidates` 同时返回 `anchors` 与 `candidates`。每个概念绑定要素编号，必须为连续原文中的短技术术语；每个要素最多6个。英文完整术语允许较长表达。短要素可直接作为一个概念。
2. 原词保留。候选区分等义、上下位、相关及未知；只有已审核接受的等义表达用于同义组。保护术语、否定、数值、方向和连接关系继续按完整目标检查。
3. 相同概念的不同表达用 OR；不同概念用 AND，每条最多2个概念、每个概念最多4个表达。词典与新增表达交替入选，防止词典占满名额。
4. 每个要素先有原词基线，再安排带已审核表达的查询、其他概念组合及单概念聚焦回退。各要素轮流使用预算。自定义智慧芽查询尊重用户指定范围，不自动扩展。
5. 自动查询附加 `PBD:[19000101 TO 基准日前一天]`。取得正文后再次按实际公开日核验；同族其他版本须有明确身份和日期映射。

抽取概念是检索规划，不能当作删除了权项中的其他必要限定。长要素没有锚点时要求重新生成，不把长句按字数硬切。原始输入、审核状态、`concept_groups`、`candidate_ids`、`sent_query`、未入选表达与成本均留档。

## 返回、融合与正文

`search_patents` 每次最多25条。合法的零命中即使没有 `results` 也记录为空；认证、额度、网络或畸形响应仍是失败，不改写成零命中。遇到平台暂停停止本批。

多查询按结果名次轮流融合，并按公开号去重。`candidate_order` 是融合后的顺序；`fetched_order` 是实际取得正文的顺序；`eligible_fetched_order` 进一步限定基准日前正文。正文尝试预算与平台返回预算分别记录，失败不会被悄悄补成成功。规则排序提示仍可查看，不能当作正文相关性或披露结论。

## 定位召回损失

冻结实际检索记录后，在评分侧执行：

```powershell
python tools/evaluate_retrieval.py --audit <search_audit或state.json> --gold <private/gold.json> --case-id <公开case_id> --output-dir final_test/retrieval-new
```

分别输出每条实际查询、平台返回池、融合前25、已取正文及合格正文的已知金标覆盖与未判文献，并定位损失阶段。没有记录的阶段为 `null`。`--aliases` 仅接受已核验的公布版本映射，不按公开号去掉 A/B 后缀猜同族。总命中数不等于返回条数，返回覆盖也不等于全文核查。

这个工具只读冻结记录，不联网，也不向 RSI 提议者回传名单。词法查询尚未完成同预算对照前，不自动切换语义工具；语义检索可作为独立策略另做平台验证，不能冒称已经接入。
