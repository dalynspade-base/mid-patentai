# 真实来源运行与评估边界

0.2.0第四阶段将工程测试、教学合成题与真实来源运行分开。实现已在本地完成，未合并、未发布；没有独立专业参考答案，不能宣称专业准确率提高。

## 三种记录分别解释

| 记录 | 说明什么 | 不能说明什么 |
|---|---|---|
| 当前工程测试 | 当前入口、材料、证据、检索和评估契约的程序行为 | 专业判断正确率 |
| 旧模块兼容测试 | 保留旧模块的兼容性 | 当前产品链路覆盖范围 |
| 34条合成eval | 作者编写的教学规则和召回参考是否符合约定 | 外部独立的专利金标准 |
| real_patent运行 | 两篇真实公开快照上的原方案和POM变更版实际输出 | 在线召回率、不同专利族盲测表现、专业正确率 |

`test_workflow.py` 的6项保留为旧模块兼容测试。分组运行器按测试ID分列，不删除历史测试、不把它们计入当前入口的覆盖数。当前工程测试内部会重复调用合成eval，因此不能把这些数量相加为独立题数。

## 可复跑命令

每轮使用新目录，避免覆盖历史产物。在项目根目录运行：

```powershell
$runId = Get-Date -Format 'yyyyMMdd-HHmmss-ffffff'
.\.venv-novelty\Scripts\python.exe -X utf8 tools/run_verification.py --output-dir ".local/verification/engineering-$runId"
.\.venv-novelty\Scripts\python.exe -X utf8 -m skills.deepeval_skill --output ".local/verification/basic-$runId.json"
.\.venv-novelty\Scripts\python.exe -X utf8 tools/run_real_patent_eval.py --fetch-sources --source-dir ".local/verification/sources-$runId" --output-dir ".local/verification/real-$runId"
```

真实集定义在 `evals/real_patent_cases.json`，从既有示例构造原方案与仅F6改为POM的方案，不包含预设结论。显式获取限两篇公开页面，不调用付费模型；每篇保留HTTP状态、原始HTML、正文快照与哈希，失败不伪造替代来源。默认无 `--fetch-sources` 时只读取已存在来源清单，不联网。

快照须为带原文定位的第2版；载入时核对清单、文件哈希、快照哈希，并重新解析HTML比对原文、编号、标题与日期。旧快照不会被原地迁移。缓存来源应在清单中明确记录原路径、取得时刻与缓存性质，不冒充本轮新获取。

## 预测与参考答案隔离

每个真实方案先以 `features / cutoff / documents` 三项输入运行现有Harness，不输入参考标签、参考行或人工确认。候选与最终复核分别导出，预测保存到 `observations.json` 后才读取可选的 `--references` 文件。实际人工复核缺失时，系统保持证据不足，不为做出A/B差异而调用 `stamp_review`。

工具另生成空白 `reference_template.json`，包括case_id、输入哈希、作者类型、参考来源、身份、时刻、判断和说明。AI草案保持 `author_type=ai / provenance=ai_draft`；不改名为 `human_reviewed`。只有声称为人工的记录、身份/带时区时刻/说明齐全且输入哈希匹配时才进入计数。程序不验证人的身份、资质、独立性或判断质量；字段齐全不能替代外部专业审阅。

JSON和Markdown分别列出真实运行数、可评分参考数、未评分数、风险参考数、漏报、错误放行、风险误报和拒答数。缺少相应参考时为 `null` / “不可计算”，不写成零。

- 风险漏报：有风险参考题中实际没有报risk的数量，包含拒答；没有风险参考题时不可计算。
- 错误放行：有参考题中实际报未发现、参考不是未发现的数量；没有合格参考时不可计算。
- 风险误报：参考未发现而实际报risk；没有合格参考时不可计算。
- 拒答：所有真实运行中保留 `insufficient_evidence` 的数量，与漏报可能重叠；这里不是内容安全拒绝。

同源原版与修改版属于同一案例族；不能称为两道独立盲测题。工程脚本也将模型输出保留在 `candidate_reviews`，不再存入最终 `reviews`；复跑输出目录必须是新目录，历史报告不修改。
