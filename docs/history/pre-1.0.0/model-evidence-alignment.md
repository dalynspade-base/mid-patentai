# 模型为主的统一证据对照

0.6.0 将本地 LlamaIndex 定位与模型辅助对照连成一个工作流程。主要目标是让模型理解原文，建立“技术要素—原文证据”对应关系，并解释证据如何支持全部限定。

## 工作流程

1. `modules.evidence_alignment.locate_evidence` 按文献建立本地索引，为每个技术要素提供最多3个段落线索；各篇独立定位，避免其他文献占满候选名额。
2. 候选沿用原文和出处，状态为 `unknown`，技术方案编号留空。本地相似度和词典匹配只影响阅读提示，不自动确认披露、关系或同一方案。
3. 用户确认后，每篇一次模型请求，同时发送全部要素、基准日、该篇全部快照、候选及阅读提示。界面预览与实际请求使用同一载荷；提示须匹配当前要素、段落、正文和快照哈希。
4. 模型独立检查全部输入原文，可以纠正本地候选，也可以引用未被本地检索命中的段落。没有提示不跳过模型理解，不按相似度阈值判断存在或缺失。
5. 每个要素输出 `disclosed / not_found / unknown`、逐字引文、段落位置、方案编号和语义依据。依据应解释技术含义、全部限定与原文的支持关系，或说明矛盾、缺口和不确定性。
6. 同一次请求还完成相关性、同一方案、充分公开及上下文完整性复核。程序验证全部要素/段落覆盖、引文、来源及输入绑定后，再交原有新颖性规则判断。

否定、连接方向、串并联、顺序、数值/单位以及互斥实施例均属于技术限定。词汇相似不能替代核查；不同文献或互斥方案不能拼接。

## 实现及兼容性

- `skills.langgraph_skill.suggest_rows` 与状态图均使用统一定位函数，不再另用首个词典包含段落生成独立对照。
- 原 `model_suggest_rows` 保留调用和候选返回方式，与主复核共享 `EVIDENCE_ALIGNMENT_INSTRUCTIONS`、本地提示构造及 `validate_evidence_rows`；仍是未完成复核的候选，不能提交为最终判断。
- 主界面使用 `model_review_documents` 一次完成每篇语义对照及复核，不先调用一次建议模型再重复复核。
- 模型请求中的 `retrieval_hints` 只保留段落引用和检索线索，完整原文位于 `document.sections`；输入超限整批拒绝，不静默截断。
- 提示词为 `novelty-review-v2-model-alignment`。当前界面的旧提示词复核需重新执行，历史快照、记录及哈希规则不修改。
- 第3版报告增加可选 `evidence_alignment` 方法说明和 `retrieval_hints` 审计字段，本地候选与最终模型对应关系分别留存。原最终复核数据结构与新颖性规则不变。

## 验证边界

`tests/test_evidence_alignment.py` 检查逐篇线索、模型纠正否定候选、采用提示之外的证据、空提示仍发送全文、预览与请求一致、拒绝失效提示、文献隔离及旧入口兼容。界面测试另检查确认后的统一载荷和提示词变更失效。

全部使用模拟模型响应验证程序行为，不证明真实模型能够正确完成专利语义理解。真实专业准确率仍需独立人工参考和隔离的盲测集。原有新颖性规则及34条基础合成回归继续保留。

2026-10-22 隔离副本验证：186项当前工程测试和6项旧兼容测试通过；基础eval分别为20/20、10/10、4/4。新增9项统一对照测试及2项界面测试。界面测试的本机回环连接受沙箱限制，改在沙箱外完成；没有调用真实模型，也没有把模拟语义响应作为真实专业正确率证据。
