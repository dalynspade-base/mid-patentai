# 2.0.0：文档 Skill、工具与 harness 分层

2026-10-30，2.0.0 架构更新。Python 导入迁移和验证结果见下文。

此前把八个 Python 入口与八份 Skill 文档同时称为 skill，且上下文义务主要由代码维护。现在只有 `.agents/skills/*/SKILL.md` 是 Skill：YAML 声明 name/description，正文说明上下文、边界、工具使用及交付。可执行函数是 tool，harness 维护运行状态与调度。

| 1.1.0 | 2.0.0 |
|---|---|
| `skills/precheck_skill.py` 包装 `PrecheckGraph` | `modules/harness.py` 单一运行器 |
| 六个 `*_skill.py` 程序入口 | `modules/patent_tools.py` 具名业务工具 |
| `skills/semantic_eval_skill.py` 转发 | 直接调用 `modules.semantic_eval.evaluate_records` |
| Python 字典维护合同/必查 | 从对应 `SKILL.md` 派生，MD 是唯一维护来源 |
| 固定六步也建立 LangGraph 图 | 直接顺序调度；移除直接依赖 |
| 硬编码提示词为主 | 请求加载当前 Skill 文档，Python 保留返回协议与校验 |

## 上下文和评估

各业务 Skill 的“上下文/核验/边界”及 `metadata.required_dimensions` 是本项目结构约定；Agent Skills 通用格式只要求 name/description 等标准元数据，不规定这些中文标题。运行器/评估器读取同一文件，模型请求只载入当前任务指令和显式材料，按需读取参考。可选脚本不会因为读取 Skill 而自动执行。

执行记录保留原有 `skill_id`、schema 与哈希含义，并新增实际文档路径/指纹；共享上下文绑定文档集合。改动指令后重建上下文与复核，不将旧结果冒充新指令运行。历史记录不补写新字段。语义规范升级为 `multidimensional-semantic-v3-document-skills`。

六维文字验收、动态必查、跨阶段衔接、基准日/范围、引用分支及修改历史保持。工程测试/模拟模型与真实专业评估分别解释。原始附件、案件、快照、既有报告与版本说明均不改写。
