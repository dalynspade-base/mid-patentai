# 1.0.1 修复说明

1.0.1 基于1.0.0提交 `1af3f3c`，修复本机兼容性与源码审阅发现的四项问题。PR #4 尚未合并时，修复PR以 `codex/release-1.0.0` 为基线，避免将完整1.0.0升级混入补丁差异。

## 行为变化

| 问题 | 修复后 |
|---|---|
| 正文业务复核能完成，独立评估因重复内容超限而整批拒绝 | 完整技能记录只在评估包中提供一份，来源通过记录内路径关联；不删改原文、不改变原业务哈希 |
| 候选重排、补正文、模型复核后扩展策略及保护术语丢失 | 重新计算沿用原材料、计划、审核和查询，保持在线检索来源 |
| 所有查询失败仍显示技能完成 | failed/partial/completed/not_executed按实际取证状态区分；成功空响应仍保留业务证据不足 |
| 依赖允许安装不支持页面参数的旧Streamlit | 最低版本提高到已验证的1.66，并提供直接依赖版本清单 |

## 兼容与升级

在已有环境执行 `python -m pip install -r requirements.txt`。希望使用本次验证的直接依赖版本时，执行 `python -m pip install -r requirements-windows-verified.txt`；此文件不锁定所有传递依赖。

旧案件、整理版本、快照、业务技能记录及其哈希不迁移、不覆盖。评估包的 `sources` 使用 `record_path` 和 `format` 指向完整 `record` 中的内容；外部自定义脚本若直接读取评估包 `sources[*].text`，应改用 `modules.semantic_eval.source_texts`，该函数同时支持新、旧评估包。业务记录的 `sources[*].text` 字段不变。

裁判提示版本变为 `multidimensional-semantic-v1.0.1`，旧网页缓存不会自动充当新版验收。完整实际请求仍限制为5万字符；确实过大的输入不会静默截断，网页会禁用发送并提示调整完整比对范围。未增加模型自动调用。
