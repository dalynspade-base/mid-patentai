# Skill上下文与权利要求版本协议

共享运行上下文由 `modules/patent_context.py` 维护。每个业务 Skill 的专用合同来自其 `SKILL.md` 的“上下文、核验、边界”，职责必查维度来自 `metadata.required_dimensions`。`modules/skill_library.py` 读取文档；`CONTRACTS`、`SKILLS` 只是派生视图，不再维护第二份规则。这三个标题与维度元数据是本项目约定，不是 Agent Skills 通用格式的额外要求。

实际记录包含 `inputs.patent_context`、直接上游 `upstream_records` 和 `skill_document` 路径/指纹；模型调用加载当前所用指令，输入仍只含明确取得的材料。共享上下文含业务 Skill 文档集合指纹，文档改变后旧上下文与模型复核需重建。旧记录不改写，也不补造当时使用的文档。

## 共享部分

`patent_context` 保存基准日 `cutoff`、CN/新颖性/Google Patents来源范围 `scope`、当前限定绑定 `features_hash`、目标 `target`、发明描述、已知领域、规则说明、相关争议主题及显式语义重点。缺失的领域标为未指定，未提供的日期保留空值；不得捏造信息。完整主流程总是传递实际基准日。

| Skill | 必要语境与职责 | 不负责的判断 |
|---|---|---|
| 材料整理 | 实际材料/确认要素、读取范围；原文与输出双向反查；权利要求继承与出处 | 补造实现；确认修改合法性 |
| 术语扩展 | 完整关系、发明描述、领域与定义；将候选放回原语境判断关系 | 改写目标限定；认定披露或法律等同 |
| 候选检索 | 目标、基准日、范围、实际查询及未读/失败记录 | 全网无相关技术；候选已完整披露 |
| 证据对照 | 逐篇原文、定义、交叉引用、实施例及组合依据；必要附图的可用性 | 跨文献/互斥方案拼接；测量示意图补参数 |
| 新颖性判断 | 完整目标、有效复核、日期链、规则与检索缺口 | 创造性、侵权、授权或修改合法性结论 |
| 报告交付 | 实际JSON与正文、版本、基准日、范围、来源和未知 | 将局部结论推广至整件申请；以保存成功代替验收 |

“需要语境”不是要求每次复制全部卷宗：只传当前判断所必需的原文与关联。缺少定义、相邻条件、交叉引用或必要附图使含义不能确定时，应补取或保留未知，不能静默截断。

## 独立/从属权利要求与修改历史

示例见 [`examples/claim_history.json`](../examples/claim_history.json)，是教学输入，不是真实申请。界面勾选“按独立／从属权利要求及修改版本比对”，导入或粘贴记录，选择版本与引用路径。

- 根对象：`schema_version=1`、`selected_version`、按日期排列的 `versions`、可选原始材料 `sources`。
- 版本：`id`、`date`、`stage`、`claims` 与 `amendment_basis`。
- 权利要求：`id`、`kind`、完整 `text`、`depends_on`、本项新增 `limitations`。每个限定须逐字来自本项原文，保持对象、关系和条件。程序不靠字符串存在证明限定提取完整，完整性由材料与语义评估核验。
- 独立项无引用；从属项引用当前版本实际存在的项。多项引用明确 `dependency_mode=any`，每条路径分别展开；循环、缺项和合并兄弟项的输入被拒绝。此检查不等于确认所有撰写形式合法。
- 修改依据：`claim_id`、`source_id`、`quote`、`explanation`。来源须有原文、位置及所属较早版本；程序核对引文存在。不提供依据时保留“未提供”，不宣称未超范围。重新编号可在本项填写 `previous_claim_id`，用于关联前一版本。

例如 `1 → 3` 与 `1 → 2 → 3` 是两个目标。分别继承路径上的限定，原文、继承出处和修改摘要进入上下文及报告。描述/实施例可解释术语，不自动导入未要求的限制；多个独立项也分别判断。

```python
from modules.harness import NoveltyHarness

# history 为已读取的记录；documents 为已取得的Google Patents快照。
state = NoveltyHarness().run(claim_history=history, claim_target="1/2",
    cutoff="2024-01-01", documents=documents)
# 不共享跨目标复核，不合并各目标结论。
batch = NoveltyHarness().run_claims(history, cutoff="2024-01-01", documents=documents)
```

`run_claims`可用 `reviews_by_target` 分别提供已绑定的复核。未传快照时按各目标执行检索；实际查询和预算分别记录。版本和路径进入限定ID，修改历史及定义等语境进入复核绑定；即使文字相同，改版、改路径或修改依据变化后旧复核也不能直接沿用。程序不自动推定有效优先权或判断修改超范围。

## 动态必查与衔接

六维全部返回。`required_dimensions`是职责下限；`semantic_focus`可显式增加必查。裁判还须按实际含义返回 `activated_dimensions`：存在功能/结果限定、机制或效果主张时检查功能与效果，存在关系/组合或评价/结论强度变化时检查对应维度。已触发的维度不能“不适用”，缺少材料不能用“不适用”绕过。

各技能先分别核验，全部完成后再核查跨步骤语义传递。范围、基准日、目标、限定及直接上游绑定的可证明冲突会阻止接纳；扩展词是否改写限定、候选是否变成事实、未知是否消失、报告是否放大结论由独立语义调用核验。投影明确去除重复原文，不替代各步骤全文评估。界面与CLI均预览实际衔接输入。

仍只给可接受、需修订、待裁决。未完成或调用失败单列，不生成完整结论。正确保留证据不足可以接受；上下文缺失到连是否履责都不能判断时才待裁决。旧记录仍可按原输入评各步骤，但缺失的衔接上下文不自动补齐或冒称已核验。
