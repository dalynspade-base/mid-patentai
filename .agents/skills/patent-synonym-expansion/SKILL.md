# 术语扩展

## 上下文

- 确认要素及其完整关系
- 发明描述、技术领域、专门定义（有则提供）
- 保护术语、扩展词的关系与用途

共享本轮基准日、CN 新颖性与本轮来源范围、完整限定、目标版本/引用路径和真实上游记录；缺口保留未知。[共享协议](../../../docs/skill-contexts.md)按需读取。

## 核验

将候选放回原关系中比较对象、范围和机制；等义、上下位、相关分别处理；检索有用不等于可替换。

## 边界

只扩展检索表达，不改写权利要求，不判技术披露或法律等同。

## 执行与交付

用 `modules.patent_tools.expand_terms` 组织查询变体；需要模型候选时调用 `modules.synonym_expansion.generate_llm_candidates`。保护原词、专名、否定、方向及单位；按语境区分等义、上下位、相关与未知。候选须明确审核，不能直接改写目标限定。详见[检索扩展协议](../../../docs/synonym-expansion.md)。

由工具保留实际输入/输出、出处和执行状态；Python 函数调用不等于模型已经阅读材料。交给下游时传递限定、未知、范围和来源。独立验收按 [六维规范](../../../docs/semantic-skills.md)，不自行评分或补造参考。

## 智慧芽适配

先识别技术对象、材料、机制、读出等不同概念；anchors绑定要素编号，摘取连续原文短术语，长权项不按字数硬切。对每个概念提供待审核的中英表达、译名或规范缩写。拟扩展的source应作为锚点，审核过的词才能进入同义组。不同概念不因“都在同一权项”就用OR混排；概念内OR、概念间AND，原词与完整限定保留。

交付概念分组、候选审核状态及未采用原因。下游需回传每个批准词是否实际下发及其查询编号；“已生成”“已审核”“已发出”“新增相关文献”分别核验。词典和模型表达交替使用预算，避免临时Skill词被词典名额挤掉。具体编译与归因见[智慧芽协议](../../../docs/patsnap-search.md)。

## RSI边界

临时Skill只优化本阶段：增加实际进入智慧芽查询的有效表达，同预算提升v1.2检索分，证据及结论不退步。查询编译、融合、预算、评分固定；不读取封存名单、参考引文、标签或测试反馈，不把个案答案写成通用例子。没有独立案例验证时不声称泛化。
