# 1.0.0 版本说明与迁移指南

日期：2026-10-26。代码版本以项目根目录 `VERSION` 为准。

## 对比基准

上一已提交版本为 `1d1bc253f7fdce4ef3fe18d00e380d6c0598cb92`，提交标题为“v0.3.0中期汇报”，该提交的 `VERSION` 实际为 **0.6.0**。它已通过 PR #3 合并到 `main`；合并提交为 `d634783408c2c2f571f8c251a04e1b1815b0e0f5`，二者代码树一致。

本文以实际 0.6.0 代码为比较对象，不将此前已完成的模型逐项复核、术语扩展、候选相关性或统一原文阅读线索重复描述为本次新增能力。

本次改变技能名称、导入路径和评测契约，属于不兼容变更，因此将主版本提升到 1.0.0。升级调整代码入口，不批量改写已保存案件或历史证据。

## 改动总览

| 方面 | 0.6.0 行为 | 1.0.0 行为及影响 |
|---|---|---|
| 业务抽象 | 框架名称作为技能边界 | 主入口和六个业务阶段明确分工，独立裁判另设入口 |
| 评估输入 | 合成参考标签、冻结候选池、历史指标 | 含实际输入、输出、来源和哈希的技能记录 |
| 验收方法 | 不同模块各自的规则/数值评测 | 统一六维语义核验与各技能职责要求 |
| 验收输出 | 历史数值指标、通过断言 | 有来源的文字发现、可接受/需修订/待裁决、反例和下一步 |
| 失败处理 | 分散在原有工具 | 业务未完成、裁判失败与质量裁决分开，缺步不认定整体通过 |
| 报告职责 | 工作流、格式化及网页共同补记录 | 交付技能集中绑定最终正文，避免自引用及旧记录冒充当前输出 |
| 基础框架 | 实现位于旧 Python skill 文件 | 仍使用 LangGraph/LlamaIndex，但实现下沉到 modules |
| 历史评测 | 与当前模块和测试混放 | 实现、CLI、测试、数据分别迁入 legacy 区域 |
| 依赖和旧业务 | 保留旧景观图/改进/写稿及必装 DeepEval | 清理停用链路，Plotly 不再直接依赖，DeepEval 为历史可选依赖 |
| 文档与运行 | 部分当前入口仍混用旧命令 | 当前操作指南、版本迁移、原文档快照和历史结果分别说明 |

## 八个入口如何协作

主入口 `skills.precheck_skill.NoveltyHarness` 配置依赖，调用 `modules.precheck_graph` 编排以下业务阶段。独立评估在业务输出冻结后调用，不作为业务判断的隐式自评分步骤。

| 业务阶段 | 实际产出 | 语义验收的关键问题 |
|---|---|---|
| 材料整理 | 要素、材料引文、未知项 | 是否补造内容、丢失关系或把未解析附件说成已理解？ |
| 术语扩展 | 候选关系、保护词、查询计划 | 是否误把上下位或相关概念当等义，改变专名、否定或限定？ |
| 候选检索 | 实际查询、候选、正文快照与失败 | 是否混淆同名提及、技术相关和实际披露，夸大读取或检索范围？ |
| 证据对照 | 要素—原文逐项对应及方案依据 | 引文是否支持全部限定，是否忽略指代、方向或互斥方案？ |
| 新颖性判断 | 保持边界的业务结论 | 是否跨文献拼接、把仅相容当必然隐含，或材料充分仍泛泛拒答？ |
| 报告交付 | 最终正文、JSON及执行记录 | 是否忠于实际结论、保留未知，并正确标明模型和历史人工来源？ |

`skills/` 仅保留上述六个子入口、主入口和独立评估入口，共八个 `*_skill.py` 文件；`.agents/skills/` 对应八份可发现技能定义。

框架实现仍实际运行：`modules/precheck_graph.py` 使用 LangGraph 状态图，`modules/evidence_retriever.py` 使用 LlamaIndex、本地词典和 TF-IDF 提供阅读线索。阅读线索与排序分值不直接决定新颖性，也不成为裁判的数值质量依据。

## 六维模型如何落实到验收

| 维度 | 本次实现的检查 |
|---|---|
| 术语与对象 | 语境等义、对象归属、上下位与相关概念区分 |
| 结构与关系 | 连接、控制方向、组合、施受角色和输入输出 |
| 逻辑与限定 | 否定、条件、范围、顺序、选择、技术数值及单位 |
| 语境与指称 | 指代、背景、引述、假设、同一方案和互斥实施例 |
| 功能与效果 | 功能限定与实现手段，不能以效果相同推定结构相同 |
| 评价与表达 | 评价措辞与技术限定混合时是否改变实际含义 |

这是任务检查模型，而非声称语义学文献规定固定六层理论。每个技能返回六维发现，各技能的必要维度在 `modules/skill_contracts.py` 声明；其余维度只有说明原因后才能标为不适用。

例如材料写“控制器**仅在温度超过设定界限时**启动冷却泵”，输出遗漏触发条件而写成“控制器启动冷却泵”，即使最终业务标签相同，也应在逻辑与限定维度指出改变，并给出恢复条件的修订动作。反之，仅措辞不同但对象、关系和全部限定保持时，不能仅因字面差异认定错误。

每个 `finding` 包括 `dimension`、`status`、`basis`、`citations`、`counterexample`、`next_action`。维度状态为满足、违反、未确定、有理由不适用；确定判断须同时引用实际输出与原始输入或来源。程序核对引文逐字存在及契约完整性，不将这种核对等同于证明语义支持正确。

裁决规则如下：有违反项则需修订；没有违反但有未确定项则待裁决；其余为可接受。裁判不得额外输出分数、概率、权重、通过率或高中低评级。

## 结果与记录的边界

业务规则仍输出四类预筛结论：

- `potential_novelty_risk`：发现单篇文献完整披露风险（预筛）。
- `no_complete_disclosure_found`：本次已复核文献中未发现完整披露。
- `insufficient_evidence`：证据不足，需要补充或复核。
- `out_of_scope`：超出本工具的新颖性范围。

业务技能执行状态为 `completed`、`partial`、`not_executed`、`failed`。只有阅读线索而没有完整有效复核的证据对照记录保持 `partial`。证据不足可以是一个已完成的业务判断，不能仅因其保守就自动判定质量合格。

语义评估输出 `acceptable`、`needs_revision`、`pending_adjudication`，执行未完成或失败时裁决为 `null`。全链评估缺少任何必需技能或有效裁判结果时，总体执行为 `incomplete`，保留已完成技能的个别意见，不生成完整验收结论。

CLI 的正常退出表示执行完成，不表示裁决为可接受。`needs_revision` 或 `pending_adjudication` 可以随完整执行正常返回；自动化调用方需要显式读取 JSON 的 `execution` 和 `verdict`。

“独立”指与业务生成分开的职责、冻结输入和另一次调用；网页沿用用户当前的模型配置，不冒称独立专家或另一模型。评估结果不会自动覆盖原业务决定。更改输入、实际输出或模型设置后，不沿用旧裁决。

## 数据绑定、参考和模型调用

技能记录契约为 `business-skills-v1`，保留技能身份、执行状态、来源说明、实际输入/输出、原文来源及 `record_hash`。评估记录契约为 `semantic-evaluation-v1`，裁判规范版本为 `multidimensional-semantic-v1`。

参考是可选项，缺少时标为 `none`。提供参考时按技能 ID 组织，并绑定实际 `record_hash`，记录 `provenance`、`author` 和 `basis`；当前支持 `independent_human_reference` 与明确标记的 `teaching_reference`。自填身份不等于系统验证了专业资质，教学参考也不变成真实专业金标准。CLI 先落盘冻结输出，再读取参考，避免参考影响被测业务生成。

实际模型调用前预检输入范围与大小。单个技能评估载荷超过当前字符上限时，整批在首个请求前拒绝，不静默截断限定或只发送半批。业务及评估的输入材料作为数据处理，不执行其中的操作指令。

语义裁判结果保存模型/服务来源、规范版本、输入绑定、时刻与逐维度证据，不持久化 API 密钥。技术数值、单位、公开日期、哈希及内部成本仍有各自用途；“纯语义验收”不意味着删除这些业务事实。

## 迁移与不兼容变更

更新到 1.0.0 后，外部调用方应同步调整以下路径。旧路径已经撤销，不提供静默兼容导入。

| 旧位置或接口 | 新位置或处理方式 |
|---|---|
| `skills.langgraph_skill.NoveltyHarness` | `skills.precheck_skill.NoveltyHarness` |
| `skills.llamaindex_skill.PatentRetriever` | `modules.evidence_retriever.PatentRetriever` |
| 旧候选辅助函数 `suggest_rows`、`model_suggest_rows` | `modules.precheck_graph`，用于保留的工程兼容；主业务使用证据对照技能 |
| `modules.novelty_report.report_payload` | `skills.report_delivery_skill.build_report`；底层格式化使用 `build_payload` / `to_markdown` |
| `skills.deepeval_skill` | 旧实现迁入 `engineering/legacy/basic_contracts.py`；当前离线契约改用 `tools/check_semantic_contract.py` |
| `modules/synonym_eval.py`、`modules/real_patent_eval.py` | `engineering/legacy/` 下对应文件 |
| `tools/run_real_patent_eval.py`、`tools/run_engineering_trial.py` | `tools/legacy/` 下对应文件 |
| `evals/fixtures.py` 与原历史 JSON | `evals/legacy/`；原内容保留其历史含义 |
| 当前与历史测试混合 | 历史指标及 DeepEval 测试迁入 `tests/legacy/`，当前契约单列 |
| 原 `run_synonym_eval.py --k / --compare-rankers` | 这些参数撤销；当前命令改为对实际记录的语义评估 |

新评估入口默认不调用模型：

```powershell
.\.venv-novelty\Scripts\python.exe -X utf8 tools/run_semantic_eval.py --records 实际导出记录.json --output-dir 新预览目录
```

在已配置进程环境变量且确认外发后，使用新目录并增加 `--run-model --confirm-external`。网页会读取 `.env`，CLI 只读取环境变量。可用 `--skill` 单评一个技能；旧报告没有 `skill_records` 时重新执行业务，不从旧指标伪造新记录。

旧数值工程回归的可运行位置与额外依赖见[历史工程说明](../../engineering/legacy/README.md)。原相似度排序评测 CLI 已撤销，相关停用业务不再维护。

## 目录清理与依赖调整

移除十个停用模块：`base_search.py`、`embedding_engine.py`、`similarity_engine.py`、`eval_ranker.py`、`landscape_map.py`、`invention_improver.py`、`patent_drafter.py`、`patent_extract.py`、`models.py`、`workflow.py`，以及旧相似度示例 `examples/eval_cases.example.json`。

旧业务测试随职责清理；模型请求失败时不暴露密钥的共享测试拆出到 `tests/test_llm_client.py`。当前规则、文献来源、取证、材料留存和有效模型复核约束继续保留，不因框架改名而删除。

运行依赖维护在 `requirements.txt`，移除 Plotly 的直接依赖和必装 DeepEval。LangGraph、LlamaIndex、scikit-learn 等仍有实际用途；DeepEval 只在安装 `requirements-engineering.txt` 后用于历史回归。当前网页、六阶段调用、离线契约及 `--current-only` 测试发现已检查可脱离历史可选包。

`tools/smoke_google.py` 改为每次新建运行目录，默认位于 `.local/verification/`，先拒绝已存在目录，再进行网络请求，避免覆盖 `reports/live_google_smoke.json` 等历史记录。

## 数据与历史保留

原始附件、`case.json`、案件整理历史、旧原文快照和哈希规则保持原有含义；每轮报告独立保存。没有新的专业复核，就不为旧记录补造人工身份、模型结果或语义验收结论。

既有 `reports/` 文件保留原字节，新增索引说明来源和版本。整理前设计文档位于 `docs/history/pre-1.0.0/`；快照保留当时的命令和相对路径语境，当前操作以 README 和当前指南为准。

真实案件、附件、凭据、依赖环境、备份和新增运行结果不纳入提交。本次大型代码重构没有删除正在使用的 `.venv-novelty`，也没有批量迁移本地案件。

## 验证结果及尚未证明的能力

目标目录完整回归通过：当前业务工程/语义契约 **189 项**，历史工程 **28 项**，均无失败或跳过；八份技能定义静态校验通过。记录为工程检查，不按次数换算语义质量或专业准确率。

覆盖的行为包括：六阶段实际记录、输入/输出/来源绑定、六维完整性、伪造引文拒绝、数值评分字段拒绝、裁决一致性、缺步和失败边界、旧结果失效、最终报告绑定，以及历史输出不可覆盖。

本次使用构造材料和模拟模型响应，没有以真实模型调用证明专业语义准确率，也没有进行新的全库召回比较。真实来源运行不等于真实金标准；真实业务能力仍需独立参考、按案例隔离的评估及有原文依据的分歧裁决。

网页附件收件不等于自动解析所有格式；完整链路仍保留用户确认。Google Patents 也不能代表全部非专利现有技术。上述边界随报告保留，不能因版本号提升而省略。

## 升级检查清单

1. 保存本地未提交工作，更新代码后按运行或历史工程需求更新依赖。
2. 将外部脚本导入和旧 CLI 参数按迁移表调整；统一使用同一 Python 环境。
3. 保留 `.local/`、原始附件和历史报告，新增运行使用新目录。
4. 运行当前工程/语义契约；需要历史 DeepEval 回归时安装可选依赖后运行完整组。
5. 用实际业务重新导出含 `skill_records` 的 JSON，再预览并确认语义评估外发内容。
6. 将业务结论、执行状态和语义验收分别解读，不把“已保存”或契约通过当成专业认可。
