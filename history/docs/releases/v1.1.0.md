# 1.1.0：具体上下文、权利要求版本与衔接核验

本地功能更新，尚未发布。相对1.0.0保持八个skill入口与普通要素模式，增加明确的专利结构输入和按职责验收。

| 方面 | 1.0.0 | 1.1.0 |
|---|---|---|
| 上下文 | 六种输入包与简短职责，部分步骤未记录基准日/范围 | 六个专用合同，共享基准日、范围、限定、目标、领域及适用规则；直接上游输出绑定 |
| 权利要求 | 一整套用户确认要素，不展开引用 | 明确的独立/从属关系与择一分支；版本选择、修改前后及原始材料依据；逐目标比对 |
| 语义必查 | 固定职责下限 | 保留下限，按含义返回动态必查；功能/效果、关系或评价等出现时不能跳过 |
| 步骤衔接 | 分别评六步 | 六步完成后独立核验限定、未知、证据身份和结论传递，参与整体裁决 |
| 案例使用 | 教学夹具与圆珠笔改动试验 | 继续保留，并按公开案例归纳领域争议底线；区分法律问题，不建专门案件库 |
| 报告 | 正文及技能记录 | 同时绑定结构化结论与正文，增加目标版本、引用路径、修改摘要和底线来源 |

## 使用与边界

界面勾选权利要求模式，导入或粘贴 [`examples/claim_history.json`](../../examples/claim_history.json) 结构的记录，选择版本和引用路径。普通确认要素输入继续可用。批量API为 `NoveltyHarness.run_claims`，完整合同见[上下文协议](../skill-contexts.md)。

权利要求原文和新增限定需要明确输入；不声称已从任意PDF自动、准确抽取所有引用与必要特征。程序核对引用、引文和来源，不以文本存在证明提取完整或修改未超范围。多项引用分支不合并，结论限于当前版本及路径。

同类争议按技术含义选题，先比较当前关系、限定、证据条件再应用；模块记录出处及适用限制。新颖性、创造性、公开充分性、支持与程序问题分别说明，后几项不能冒充新颖性结论。模型或摘要未提供的案件事实不补造。

## 兼容及外发

- `Feature`与原文快照格式保持兼容；新版本/路径限定和上下文绑定共同使旧复核失效。新模型复核保存 `review_context_hash`；缺少上下文绑定的旧模型复核须重新执行。旧人工记录保留原哈希；用于新权利要求/定义语境时也须重新绑定。
- `business-skills-v1`记录外层不变，在输入内增加上下文和上游绑定。历史记录不修改，也不补造基准日、来源或跨skill验收。
- 裁判规范升级为 `multidimensional-semantic-v2-context`。新上下文记录须返回 `activated_dimensions`；旧的裁判结果不能当作新规范的实际运行。旧记录仅评价个别技能时明确 `assessment_scope=individual_skills_only`。
- 六步语义验收之后可增加一次衔接请求；六步未完成则不形成整体裁决。界面与CLI计划同时展示该请求，实际调用仍沿用独立外发确认。超过输入上限整体拒绝，不截断原文或冒用旧结论。
- 报告继续使用兼容的schema 3，新增字段为可选扩展。原始附件、案件清单、历史整理、快照及结果不覆盖。Google Patents证据来源约束保持有效，法院/CNIPA资料在案例模块作解释参考。

## 验证

隔离副本通过205项当前工程检查、28项历史工程检查，无失败或跳过；八份技能定义及文档链接校验通过。新增检查覆盖分支继承、独立/从属结论差异、改版/定义变更后旧复核失效、修改依据、快照与上游绑定、动态必查、跨skill裁决和真实界面导入。响应采用教学事实及模拟模型，未调用真实付费模型，不证明专业语义准确率。
