# Google Patents 连接保护与恢复

503若包含自动查询提示，程序停止整批检索及正文获取，并在`.local/google-patents/network.sqlite3`保存暂停状态。关闭程序或重新启动不会自动清除该状态。普通503、429及超时最多尝试3次，等待5/15秒；耗尽后暂停5分钟。长于30秒的Retry-After会暂停，等待人工检查后恢复。

真实请求共用一个跨进程队列，最小间隔5秒。这个间隔是本项目的保守起点，不是Google公布的许可频率，不能保证服务不再拦截。不要同时从其他脚本反复探测。

先在浏览器人工确认访问情况；有验证码由本人处理。核对系统代理、共享网络是否有其他程序持续请求，但本工具不修改网络设置。浏览器能打开页面只证明浏览器当时可用，程序路径仍需小规模验证。

在项目根目录执行（默认只读本机路由及本地状态，不发送请求）：

```powershell
.\.venv-novelty\Scripts\python.exe -X utf8 tools/check_patent_network.py
```

人工确认网络恢复后，显式清除暂停并尝试一条公开查询、最多一篇正文；不调用模型：

```powershell
.\.venv-novelty\Scripts\python.exe -X utf8 tools/check_patent_network.py --resume --probe --output .local/diagnostics/network-recovery-new.json
```

已暂停时，不使用`--resume`的探测不会发送新请求。输出文件必须使用新名称。路由信息仅保存是否配置及是否为本机代理，不保存代理凭据或外部地址。仅支持既有Google官方入口，旧入口最终仍依赖同站点。

有效非空检索结果缓存1小时，解析成功的正文缓存30天。绑定完整请求及参数，正文语言分别缓存；正文回放保留原获取时间及快照哈希，完整内容不截断。只有缓存不存在/过期的部分才重新请求。`.local/google-patents/`有原文和检索材料，保持本地，勿上传。缓存响应和实际网络请求在本地events表分别记录，逻辑查询次数不等于HTTP次数。

RSI失败后使用相同Skill、公开输入、预算及模型设置重新运行时，会沿用未完成的查询计划和有效响应缓存；仍需使用新的运行输出目录。已完成试跑清除查询计划，下一次配对重新规划。网络恢复不代表此前失败试跑已经完成，不补造历史分数。

缓存不会导入其他案件的人工结论或模型判断，也不改变原始附件、已保存原文、正式八份Skill和评估标准。
